Going live: what we show for real on demo day

Live Callback API — POST /api/v2/conversations/callbacks

  • No named agent needed. The callback goes to a queue and the next available demo agent gets it, the same way CAA would run it.
  • Context rides along. data lands as participant attributes, so the callback script shows the member #, level and roadside request.
  • Real phone rings. The agent accepts, Genesys dials the presenter's mobile, and the room hears it.
  • One API call from the page. No backend to build for the demo.

Keep mocked Create call — POST /api/v2/conversations/calls/user/{userId}

  • Rings a named agent's phone first, then dials the member. No queueing, no next-available agent.
  • Fits one moment only: an agent already chatting with the member taps "Call member".
  • Adds a second live dependency (a specific agent on a specific station) for little extra value in the room.
  • We can mention it as the chat-to-voice option and show it in the inspector.
LIVE: Call me → callback → agent accepts → presenter's phone rings MOCKED: sign-in, Messenger SDK chat, roadside request, AI agent

How the live path fits together

For the demo, the page holds a short-lived token for a demo user who can only create callbacks. In production, the app calls CAA's API gateway, which calls Genesys server-to-server.
